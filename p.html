Part 1

What is a Processor?

The brain of the computer – it takes instructions and data as inputs and manipulates the data.

Each processor has an instruction set – a collection of operations it can perform. Computer architectures are classified into two types based on their instruction sets:

CISC

Complex Instruction Set Computer – rich, multi‑cycle instructions.

Foundation

The Core Role of a Processor

Brain of the System

The processor receives inputs consisting of instructions and raw data to perform data manipulation.

Instruction Set Architecture (ISA)

The defined set of operations supported by the hardware, forming the interface between software and silicon.

Architectural Classifications

ISA design splits computer architectures into two primary schools of thought:

CISC: Complex Instruction Set Computer RISC: Reduced Instruction Set Computer
Historical Context

Pre-1970 Memory Constraints

Slow & Expensive RAM

Memory was extremely constrained and costly, requiring programs to take up minimal space.

Compiler Challenges

Translating complex HLL constructs into low-level machine code was difficult, tedious, and error-prone.

Bridging the Gap

Hardware architects created compact instructions to simplify compiler design and save memory space.

CISC Era

The Era of Compact Instructions

Doing More in One Command

A single CISC instruction automatically handles multi-step operations:

MULT [A], [B]
  • Fetches values directly from memory locations A and B.
  • Loads data implicitly into internal registers.
  • Performs multiplication and writes back to memory.

Software & Memory Savings

Compact instructions drastically reduced binary file size when every byte of RAM was costly.

Compiler Simplification

By delegating multi-step execution logic to silicon hardware, compilers required significantly less complexity.

The Cost of Complexity

Silicon Burden & Natural CISC

Hardware Burden

Shifting complexity into hardware required supporting hundreds of specialized silicon instructions.

Physical Drawbacks

Processor designs grew dense and expensive, consuming substantial power and generating excessive heat.

Retroactive Terminology

CISC evolved organically; the term "CISC" was coined retroactively after RISC was conceptualized. Computer architects didn't explicitly set out to create Complex Instruction Set Computers — they naturally evolved due to the conditions existing at that time.

Part 2

The RISC Revolution

Discovering the 80/20 discovery and fundamentally rethinking processor design.

📊 "20% of instructions are used 80% of the time"

— The discovery that changed processor design forever

The Turning Point

The 80/20 Discovery

The 80/20 Rule Discovery

In the early 1980s, empirical studies revealed that 80% of a program's execution used only 20% of the instruction set. Most complex CISC instructions were rarely used, taking up valuable silicon real estate for minimal gain.

The RISC Philosophy

Engineers stripped away complex operations, designing processors around a small set of simple, fast, heavily-used instructions. This streamlined approach was named Reduced Instruction Set Computer (RISC).

Code Execution

Code Execution Comparison

CISC Execution (1 Line)

MULT [A], [B]
  • Single Complex Command
  • High instruction density
  • Variable-length bytes
  • Multiple internal clock cycles
  • Direct memory access

RISC Execution (4 Lines)

LOAD R1, [A]
LOAD R2, [B]
PROD R3, R1, R2
STORE R3, [A]
  • Load/Store Architecture
  • Multiple simple instructions
  • Uniform fixed length
  • Single clock cycles
  • Register-to-register operations
RISC Advantage

Pipelining & Execution Speed

RISC's fixed-length instructions enable efficient pipelining — an assembly-line approach to instruction execution.

Instruction t1 t2 t3 t4 t5 t6 t7 t8
Instr. 1 IF ID IE RW -- -- -- --
Instr. 2 -- IF ID IE RW -- -- --
Instr. 3 -- -- IF ID IE RW -- --
Instr. 4 -- -- -- IF ID IE RW --
Instr. 5 -- -- -- -- IF ID IE RW
# Stages 1 2 3 4 4 3 2 1
Stage engaged No instruction IF: Fetch  |  ID: Decode  |  IE: Execute  |  RW: Write-back
Pipeline: When one instruction is being executed, the next is being decoded, and the third is being fetched — all in one clock cycle.
Hardware Efficiency

Reallocating Saved Transistors

More Registers

Saved silicon was reallocated to large register files, enabling fast data access directly inside the CPU.

On-Chip Caches

Transistors were used to build dedicated L1/L2 caches, eliminating external RAM bottlenecks.

Math Coprocessors

Dedicated Floating Point Units (FPUs) were added to accelerate complex floating-point mathematics.

With simpler RISC hardware, saved transistors were used to increase registers, cache, and math coprocessors — improving performance without increasing power.
The Math

The Performance Equation

Execution Time = Instruction Count × CPI × Clock Cycle Time

CISC Optimization Strategy

  • Reduces Instruction Count using dense, multi-operation commands
  • Accepts higher CPI (typically 2 to 10+ cycles per instruction)

RISC Optimization Strategy

  • Minimizes CPI (~1 cycle) and Clock Cycle Time
  • Accepts higher overall Instruction Count

Real World

Real-World Industry Dominance

CISC: Intel x86 & AMD

Dominates PC desktops, laptops, and enterprise data center servers where backward compatibility and legacy software support are paramount.

Intel AMD x86-64

RISC: ARM & Apple Silicon

Dominates mobile phones, tablets, IoT, wearables, and modern high-efficiency computers (e.g. Apple M-series) due to superior performance per watt.

ARM Apple M Qualcomm
CISC dominates in PCs & servers • RISC dominates in mobile & embedded
Specific Chips

Real-World Examples

CISC: Intel Core i9 (x86)

Key Features:

  • Massive instruction set (over 1000 instructions)
  • Variable instruction length (1–15 bytes)
  • Complex addressing modes
  • High clock speeds (5+ GHz)
  • Microcode-controlled execution

Used in high-performance desktops, gaming, servers.

Example: MULT [A], [B]

RISC: Apple M3 (ARM)

Key Features:

  • Small, fixed-length (32-bit) instructions
  • Load/Store architecture
  • Large register file (32+ registers)
  • Efficient pipelining
  • High performance per watt

Used in MacBooks, iPads, iPhones, and high-efficiency laptops.

Example: LOAD R1, [A] PROD R3, R1, R2
